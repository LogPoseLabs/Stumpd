
# Stump'd 🏏

A cricket scoring app for casual and club-level matches — ball-by-ball live scoring, groups and
player stats, a Player of the Match / impact score engine, tournaments, and multi-device sync, all
usable fully offline and backed by Firebase when you want to share.

Android app in Kotlin + Jetpack Compose, with a small React web companion for viewing matches and
live scores from a browser without installing anything.


## Features

- **Live scoring** — ball-by-ball entry with wides, no-balls, byes, extras, partnerships,
  fall-of-wickets, the joker rule, powerplay, and a configurable super over for tied matches.
- **Groups** — a group has its own roster, match defaults (overs, wide/no-ball runs, powerplay,
  short pitch, etc.) and an owner; members join by invite code.
- **Tournaments** — persistent named teams with fixed squads, single or double round robin,
  groups + knockout, or straight knockout, with an auto-generated schedule, a standings table
  (points, net run rate), and per-tournament stats leaders.
- **History & corrections** — every match is saved with full ball-by-ball data; a mis-scored match
  can be corrected after the fact (runs, wickets, bowler assignment) without hand-editing anything.
- **Stats, records & rankings** — career batting/bowling figures, milestones, head-to-head,
  captain stats, and an ICC-inspired player rating system.
- **Live spectating** — share a link to a match in progress and watch the score update in real
  time from another phone or a browser, no login required on the viewer's side.
- **Cloud sync** — Room is the source of truth and the app works fully offline; Firestore syncs
  matches, players and groups across a scorer's own devices and shares grouped data with group
  members, respecting ownership (only a group's owner can write its matches/tournaments).

## Project layout

```
app/                 Android app (Kotlin, Jetpack Compose, Hilt, Room)
  src/main/          App code
  src/test/          Unit tests (JVM, Robolectric)
  src/androidTest/   Instrumented tests
  schemas/           Exported Room schema JSON, one per DB version
web/                 Browser companion (React + TypeScript + Vite + Tailwind) —
                     group dashboards, match scorecards, live match viewing
docs/                Living design docs (UI revamp, etc.)
firestore.rules      Deployed Firestore security rules — keep in sync with the Firebase console
```

## Getting started

### Prerequisites

- Android Studio (or the command-line SDK) with JDK 17
- A Firebase project with Firestore enabled, if you want cloud sync/spectating — see
  [`FIREBASE_SETUP.md`](FIREBASE_SETUP.md) for the full walkthrough. Without it, the app still
  works fully offline; sync-related features just stay dark.

### Build the Android app

```bash
./gradlew assembleDebug        # or assembleRelease
./gradlew testDebugUnitTest    # unit tests
./gradlew ktlintCheck          # lint
```

Drop your `google-services.json` into `app/` before building if you want Firebase features — it's
git-ignored on purpose (see below).

### Run the web companion

```bash
cd web
npm install
npm run dev
```

It needs its own Firebase web config — see `web/src/firebase.ts`.

## Security

`firestore.rules` is the actual security policy enforced by Firestore, not just documentation —
if you change access rules, update this file **and** deploy it
(`firebase deploy --only firestore:rules`), or the repo will silently drift from what's live.

## What's git-ignored, and why

- `app/google-services.json`, `*.jks` / `*.keystore`, `signing.properties` — secrets. Configure
  these locally or via CI secrets, never commit them.
- `build/`, `.gradle/`, `web/node_modules/` — fully regenerated by `./gradlew` / `npm install`.
  If you're zipping the project to move it between machines, exclude both — they're most of the
  size and none of it is needed to rebuild.

## CI

Every push and PR to `main` runs unit tests and ktlint via GitHub Actions
(`.github/workflows/pr-checks.yml`); `android-release.yml` handles release builds.
